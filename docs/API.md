## Transport & endpoint

| Property | Value |
|----------|-------|
| Transport | Streamable HTTP (JSON-RPC 2.0 over HTTP POST) |
| Endpoint | `https://<jeedom-host>/plugins/jeedomMCP/api/mcp.php` |
| Content-Type | `application/json; charset=utf-8` |

**Health check** (no auth required):

```bash
curl -s https://<jeedom-host>/plugins/jeedomMCP/api/mcp.php
# {"status":"ok","server":"JeedomMCP-PHP"}
```

**POST request format** (JSON-RPC 2.0):

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "devices_list",
    "arguments": {}
  }
}
```

**Response format**:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": { ... }
}
```

## Authentication

All POST requests must include the API key in the `X-API-Key` header.

```
X-API-Key: <48-character hex key>
```

The key is generated on plugin activation and stored in Jeedom's configuration under `mcpApiKey`. It can be regenerated from the plugin configuration page (invalidates existing connections).

Requests with a missing or invalid key return HTTP 401:

```json
{"error": "Unauthorized"}
```

## Admin actions

These actions use Jeedom session authentication (nonce), **not** the API key. They are called from the Jeedom admin UI.

### `GET ?action=generateApiKey` + `POST nonce=<nonce>`

Regenerates the MCP API key.

**Query parameter**: `action=generateApiKey`

**POST body**: `nonce=<one-time token>` (generated by the plugin configuration page)

**Response**:

```json
{"success": true, "key": "<48-hex-chars>"}
```

Returns HTTP 403 if the nonce is missing, invalid, or expired.

## MCP protocol methods

These are JSON-RPC methods sent in the `method` field.

### `initialize`

Handshake method called by the MCP client on first connection.

**Response**:

```json
{
  "protocolVersion": "2024-11-05",
  "capabilities": {"tools": {}},
  "serverInfo": {"name": "JeedomMCP-PHP", "version": "1.0.0"},
  "instructions": "Control a Jeedom home automation system. ..."
}
```

### `notifications/initialized`

Notification sent by the client after `initialize`. No response body — returns HTTP 202.

### `ping`

Liveness check.

**Response**: `{}`

### `tools/list`

Returns the full list of available tools with their names, descriptions, and input schemas.

**Response**:

```json
{
  "tools": [
    {
      "name": "devices_list",
      "description": "...",
      "inputSchema": { "type": "object", "properties": { ... } }
    }
  ]
}
```

The list is filtered by ACL: tools the current API key is not authorized to call are excluded.

### `tools/call`

Invokes a tool by name.

**Params**:

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Tool name (e.g. `devices_list`) |
| `arguments` | object | Tool-specific parameters |

**Response** (success):

```json
{
  "content": [{"type": "text", "text": "{...}"}]
}
```

**Response** (tool-level error):

```json
{
  "content": [{"type": "text", "text": "{\"error\": \"...\"}"}],
  "isError": true
}
```

## Device tools

### `acl_list`

Returns the active ACL mode and the full list of tools the current client is authorized to call. Always accessible regardless of ACL mode.

**Parameters**: none

**Returns**:

```json
{
  "mode": "read_execute",
  "authorized_tools": ["acl_list", "devices_list", ...]
}
```

### `devices_list`

Lists all enabled Jeedom equipment with state and actions. Paginated.

**Parameters**:

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `categories` | string[] | no | Filter by category: `heating`, `security`, `energy`, `light`, `opening`, `automatism`, `multimedia`, `default` |
| `room_ids` | int[] | no | Filter by room ID |
| `include_hidden` | bool | no | Include invisible devices (default: `false`) |
| `include_state` | bool | no | Include state map per device (default: `true`) |
| `include_actions` | bool | no | Include actions array per device (default: `true`) |
| `include_historical` | bool | no | Include list of historized command names (default: `false`) |
| `with_plugin_info` | bool | no | Include `managed_by` (plugin name) and `plugin_id` (internal ID) |
| `managed_by` | string | no | Filter by plugin name — requires `with_plugin_info=true` |
| `limit` | int | no | Max results (default: 50, 0 = unlimited) |
| `offset` | int | no | Skip N results (default: 0) |

**Returns**:

```json
{
  "total": 12,
  "offset": 0,
  "limit": 50,
  "items": [
    {
      "id": 42,
      "name": "Salon",
      "description": "...",
      "room_id": 5,
      "categories": ["light"],
      "is_visible": true,
      "managed_by": "openzwave",
      "plugin_id": "7",
      "state": {"Luminosité": 80, "Etat": 1},
      "actions": [{"id": 101, "name": "On", "subType": "other"}, {"id": 102, "name": "Off", "subType": "other"}, {"id": 103, "name": "Luminosité", "subType": "slider"}],
      "available_historical": ["Luminosité", "Consommation"]
    }
  ]
}
```

### `device_get_history`

Queries historized values for a command (sensor data, power consumption, etc.).

**Parameters**:

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `equipment_id` | int | no | Equipment ID — use with `command_name` |
| `command_name` | string | no | Command name from `available_historical` |
| `start` | string | no | ISO 8601 or `YYYY-MM-DD` (default: 7 days ago) |
| `end` | string | no | ISO 8601 or `YYYY-MM-DD` (default: now) |
| `aggregate` | string | no | `stats` (default), `raw`, `avg`, `min`, `max`, `sum` |
| `group_by` | string | no | `hour` or `day` — for time-series aggregates |

**Returns (aggregate=stats)**:

```json
{
  "command_name": "Température",
  "unit": "°C",
  "start": "2026-04-17T00:00:00",
  "end": "2026-04-24T00:00:00",
  "aggregate": "stats",
  "stats": {
    "avg": 21.3, "min": 18.1, "max": 24.6,
    "sum": 3624.1, "count": 170, "last": "2026-04-24T09:15:00"
  }
}
```

**Returns (aggregate=avg, group_by=day)**:

```json
{
  "aggregate": "avg",
  "group_by": "day",
  "count": 7,
  "points": [
    {"datetime": "2026-04-17", "value": "20.8"},
    {"datetime": "2026-04-18", "value": "21.1"}
  ]
}
```

### `command_execute`

Executes one or more action commands. Accepts a batch of command references.

**Parameters**:

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `commands` | object[] | yes | Array of command references (see below) |

Each command reference:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | int | no | Single command ID |
| `ids` | int[] | no | Multiple command IDs sharing the same value |
| `value` | string | no | Required for `slider`, `color`, `message` subTypes |

**Returns**:

```json
{"success": true}
```

## Extension tools

Extension tools are provided by optional PHP extensions shipped with or installed alongside JeedomMCP. They follow the naming convention `ext_{pluginId}_{toolName}`.

All extension tools require the `ext_{pluginId}.execution` ACL permission. They are not available in the `read_execute` or `read_execute_describe` ACL presets — only in `full`, `full_admin`, `full_admin_secrets`, or `custom` mode.

For the extension authoring guide, see [mcp-plugin-extension.md](mcp-plugin-extension.md).

## ACL reference

### Modes

| Mode | Domains allowed |
|------|----------------|
| `read_execute` | `devices.read`, `devices.execution`, `rooms.read`, `scenarios.read`, `scenarios.execution`, `messages.read`, `messages.execution` |
| `read_execute_describe` | Same as above + all `*.set_description` |
| `full` | All non-admin domains (devices, rooms, scenarios, messages — full CRUD) |
| `full_admin` | All domains except `admin_plugin_secrets` |
| `full_admin_secrets` | Unrestricted — all domains including `admin_plugin_secrets` and `ext_*` |
| `custom` | Granular per-domain/operation flags stored in plugin config |

Extension tools (`ext_*`) are never accessible in `read_execute` or `read_execute_describe`. They require `full`, `full_admin`, `full_admin_secrets`, or `custom` with explicit permission.

### Domains & operations

| Domain | Operations |
|--------|-----------|
| `devices` | `read`, `execution`, `set_description`, `update`, `delete` |
| `rooms` | `read`, `create`, `update`, `set_description`, `delete` |
| `scenarios` | `read`, `execution`, `create`, `update`, `set_description`, `delete` |
| `messages` | `read`, `execution` |
| `admin_plugins` | `read`, `create`, `update`, `execution`, `delete` |
| `admin_plugin_secrets` | `read`, `update` |
| `admin_logs` | `read` |
| `admin_system` | `read`, `update` |
| `ext_{pluginId}` | `execution` |

## Error reference

### HTTP errors

| Status | Meaning |
|--------|---------|
| 200 | Success |
| 202 | Notification acknowledged (no body) |
| 400 | Bad request (parse error or unknown admin action) |
| 401 | Missing or invalid API key |
| 403 | Admin action nonce invalid or expired |
| 405 | Method not allowed (non-GET, non-POST) |

### JSON-RPC errors

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {"code": -32601, "message": "Method not found: foo"}
}
```

| Code | Meaning |
|------|---------|
| `-32700` | Parse error — request body is not valid JSON |
| `-32601` | Method not found |

### Tool-level errors

When a tool itself fails (e.g. ACL denied, equipment not found), the response uses HTTP 200 with `isError: true`:

```json
{
  "content": [{"type": "text", "text": "{\"error\": \"Equipment 99 not found\"}"}],
  "isError": true
}
```

Common error messages:

| Situation | Error message |
|-----------|--------------|
| ACL denied | `Operation 'delete' on 'devices' is not authorized` |
| Tool not found | `Unknown tool: foo` |
| Missing parameter | `Missing required parameter: equipment_id` |
| Resource not found | `Equipment 99 not found` |
